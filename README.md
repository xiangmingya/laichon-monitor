# 莱充充电监控

适用于青龙面板的 Python 脚本。自动发现莱充电动车的充电订单，默认在连续两条有效功率采样低于 **30 W** 时自动停止充电，查询确认订单结束后通过 ShowDoc 推送微信通知；接口异常及停止结果待确认时也会通知你。

支持两个账号及每个账号下的多个充电订单，无需手动填写订单号。正常查询和无充电订单时不发送消息。

## 功能

| 功能 | 说明 |
| --- | --- |
| 自动查找订单 | 查询当前月和上个月，覆盖跨月充电 |
| 低功率自动停止 | 默认连续两条真实采样低于 30 W 时提交停止请求 |
| 结束结果确认 | 只有详情状态为 7 才通知已结束，通知包含当前结算和退款金额 |
| 双账号监控 | 分别查询、保存状态，通知注明所属车辆 |
| 防重复操作 | 已返回成功的停止请求只继续核对，不重复提交；同类结果通知去重 |
| 接口异常提醒 | HTTP 错误、网络失败、业务错误或异常响应时通知 |
| 异常恢复 | 持续异常只提醒一次，查询恢复后自动重新启用提醒 |
| 推送失败重试 | 已结束订单的通知也会保存，下一轮补发，不会因此重复停止 |
| 无额外依赖 | 使用 Python 标准库，无需安装 requests |

**本版本会实际停止充电。30 W 是用户设定的停止阈值，不代表电池已经充满。两个账号使用同一阈值，所有符合条件的充电订单都会自动停止。**

## 运行环境

- Python **3.9 或以上**。
- Linux 青龙面板；也可在 Linux/macOS 本地运行。
- 使用 `fcntl` 文件锁，不支持直接在原生 Windows 上运行。
- 有效的莱充账号凭证和 [ShowDoc 专属推送地址](https://push.showdoc.com.cn)。

## 青龙安装

### 1. 上传脚本

将 [laichon_monitor.py](laichon_monitor.py) 上传至青龙的 **脚本管理**。更新时覆盖同名脚本，保留原有状态文件。

### 2. 配置环境变量

在青龙的 **环境变量** 中添加并启用：

| 变量 | 必填 | 内容或默认值 |
| --- | --- | --- |
| `LAICHON_TOKEN` | 是 | 第一账号的 Authorization，可带 `bearer ` 前缀，也可只填令牌 |
| `LAICHON_OPENID` | 是 | 同一账号请求头中的 openid |
| `SHOWDOC_PUSH_URL` | 是 | 完整 ShowDoc 地址：`https://push.showdoc.com.cn/server/api/push/你的token` |
| `LAICHON_NAME` | 否 | 第一账号显示名称，默认 `我的车` |
| `LAICHON_TOKEN_2` | 否 | 第二账号的 Authorization，须与 OPENID_2 成对填写 |
| `LAICHON_OPENID_2` | 否 | 第二账号的 openid |
| `LAICHON_NAME_2` | 否 | 第二账号显示名称，默认 `老婆的车` |
| `LAICHON_POWER_THRESHOLD` | 否 | 自动停止阈值，单位 W，默认 `30`，须大于 0 |
| `LAICHON_STATE_FILE` | 否 | 第一账号状态文件，默认脚本旁的 `.laichon_state.json` |

从自己已登录的莱充小程序请求头中获取 TOKEN 和 OPENID；两者必须来自同一账号。凭证失效后重新获取并更新，脚本不会自动登录或刷新 Token。

**不要用逗号拼接两个账号的凭证。** 第二账号使用带 `_2` 的两个变量，不填写时只监控第一账号。两个账号共用 ShowDoc 地址、功率阈值和一个定时任务；某个账号接口失败会继续查询另一个账号。

如果两辆车的订单都属于同一个微信账号，只配置第一账号即可，脚本会监控该账号下所有返回的充电中订单。

**从旧版升级：如果已设置 `LAICHON_POWER_THRESHOLD=20`，请改成 `30` 或删除该变量以使用默认值。** 覆盖同名脚本并保留状态文件；旧版“已提醒”记录不会阻止新版自动停止。更新后的任务首次运行时，已有订单最后两条有效采样符合条件就会提交停止请求。

### 3. 创建定时任务

| 项目 | 内容 |
| --- | --- |
| 名称 | `莱充充电监控` |
| 命令 | `task laichon_monitor.py` |
| 定时规则 | `*/5 * * * *` |

保存后执行任务，查看是否成功发现充电订单和输出功率。符合停止条件的订单会立即按规则处理。

模拟日志：

```text
[我的车] 找到 1 个充电中订单；自动停止阈值 < 30 W（连续两条采样）
[我的车] 订单 示例订单：最近两条功率：326.3 → 326.9 W
[老婆的车] 找到 0 个充电中订单；自动停止阈值 < 30 W（连续两条采样）
```

### 4. 可选：测试推送

```text
task laichon_monitor.py --test-notify
```

该命令只使用 SHOWDOC_PUSH_URL，会发送一条真实测试消息，不查询莱充账号，也不改变订单提醒状态。无需定时执行。

## 低功率自动停止规则

从 `charging_details` 读取功率，按数字键表示的秒数排序，结合 `startTimestamp` 确定采样时间。只有同时满足以下条件才提交停止请求：

1. 订单状态为 `3`，仍在充电中。
2. 最新采样距离充电开始至少 10 分钟。
3. 最后两条功率均**严格小于**阈值，默认 30 W；等于阈值不触发。
4. 两条采样间隔为 4～7 分钟。
5. 最新采样没有超过 15 分钟未更新，也没有明显的未来时间异常。
6. 订单尚未确认结束，且本次有新的采样，或调整了阈值；待处理的停止请求按下方重试规则处理。

“连续两条”指设备采样记录，不是重复执行两次脚本。首次运行时，最后两条历史采样已符合条件就会直接停止。数据缺失、陈旧或无效时不当作 0 W，并在日志中提示。例如 `1.9 → 33.6 W` 不会触发停止。

停止接口为 `POST /api/app/ebike/order/stop`，JSON 请求体为 `{"order_no":"订单号"}`，使用对应账号的凭证。

处理流程：

1. 提交前保存待处理状态，接口返回 `code: 0` 后保存已接受状态。
2. 再查订单详情，订单号必须匹配，状态为 `7` 才确认已结束。
3. 若仍在充电或暂时查不到结果，推送“停止结果待确认”，下一轮继续查询。已接受的停止请求不会重复提交。
4. 若停止请求超时或失败，推送“自动停止请求异常”；下一轮先查详情。已结束则不重试，仍在充电且当前有效采样依然符合阈值时才重试停止。
5. 待确认订单即使不再出现在充电列表中，也会继续查详情；已完成订单即使不在列表中，也会补发未成功的结果通知。

成功通知示例（示例数据）：

```text
标题：我的车：莱充充电已结束

车辆：我的车
订单：示例订单
地点：示例站点 示例车棚
设备：示例设备，插口：1
最近两条功率：29.8 → 29.1 W
采样时间：2026-10-11 23:30:00
功率连续两条采样低于 30 W，触发自动停止。
已查询确认订单为已完成（状态 7）。
结束时间：2026-10-11 23:30:34
停止原因：远程手动停止
充电时长：458 分钟
预付金额：3.00 元
当前结算金额：2.48 元
当前退款金额：0.52 元 已退费
```

“远程手动停止”是平台接口返回的原因；脚本调用同一停止接口也可能得到该文字。金额按接口当时返回值展示，结算或退款状态可能稍后更新；脚本不会持续追踪退款。

## 接口异常与 Token 失效

订单列表或详情接口请求失败时，会通过 ShowDoc 发送“莱充接口请求异常”，注明对应车辆；停止请求异常或停止后的首次确认失败，会发送对应订单的停止异常或待确认通知：

- HTTP 401/403 或非零业务码：提示检查凭证，登录失效时更新对应账号的 TOKEN 和 OPENID。
- 网络连接失败：提示检查网络，不直接认定为 Token 过期。
- 持续异常：同一账号只提醒一次，避免每 5 分钟重复发送。
- 查询恢复：一次完整账号查询成功后清除异常标记，下次异常可重新提醒。

ShowDoc 仅返回 `error_code: 0` 时才算接受推送请求；服务接受不等于微信最终送达。若 ShowDoc 同时不可达，日志会记录错误，下一轮尝试重发。通知直接调用 ShowDoc，不依赖青龙系统通知配置。

## 没有充电订单时的请求

每轮会查询每个账号当前月、上个月的订单列表；每个充电订单再查询一次详情。

| 场景 | 每轮请求数 |
| --- | --- |
| 一个账号，无充电订单 | 2 次列表请求 |
| 两个账号，无充电订单 | 4 次列表请求 |
| 有充电订单 | 每个充电订单增加 1 次详情请求 |
| 首次触发停止 | 增加 1 次停止请求及 1 次详情确认请求（停止请求失败时不会立即确认） |
| 有待确认订单 | 每个订单查询详情；仅未接受且仍符合条件的请求可能重试停止 |

无订单时仍查询列表，以便发现下一次充电和登录失效。正常无订单时不推送。平台限流规则尚未确认，可按实际情况调整定时频率。

## 状态文件

```text
.laichon_state.json       # 第一账号的采样、停止状态、待发送通知和接口异常记录
.laichon_state_2.json     # 第二账号的独立记录
.laichon_state.lock       # 防止监控任务同时运行
```

自定义状态路径时，第二账号在扩展名前追加 `_2`，例如 `monitor.json` 对应 `monitor_2.json`。

更新脚本时保留状态文件；删除后会丢失停止请求及通知记录，仍在充电且符合条件的订单可能重新提交停止请求。真实凭证、推送地址和运行状态不需要提交到仓库，`.gitignore` 已排除默认状态文件、`.env`、日志和 Python 缓存；自定义状态文件应放在仓库外。

在 Linux/macOS 上配置相同环境变量后运行：

```sh
python3 laichon_monitor.py
```

运行自动化测试：

```sh

```

目前有 30 项测试，覆盖 30 W 严格阈值、单次低功率后回升、重复及陈旧采样、跨月查询、账号独立处理、停止超时及延迟确认、旧版状态兼容、异常去重与恢复、已结束订单推送失败重试和 ShowDoc 响应校验。测试使用模拟接口，不访问真实账号，不停止真实订单，也不发送微信消息。

## 当前限制

- 莱充接口来自提供的请求样本；平台改变格式后可能需要调整脚本。
- 列表响应没有提供分页信息，本版只读取返回的 `data.list`，无法保证获取未返回的分页订单。
- 最多配置两个账号，支持每个账号下多个充电订单。
- 不会自动登录或刷新 Token；只通知本脚本处理的停止结果，不单独追踪其他手动结束的订单。
- 停止接口返回成功但订单一直未变为 7 时，会继续核对并保留待确认状态，需要用户查看小程序。
- 功率阈值用于决定停止时机，不能证明电池已经充满。
