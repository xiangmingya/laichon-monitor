# 莱充充电监控

适用于青龙面板的 Python 脚本。自动发现莱充电动车的充电订单，在功率持续低于 **20 W** 时通过 ShowDoc 推送微信提醒；接口请求失败时也会通知你。

支持两个账号及每个账号下的多个充电订单，无需手动填写订单号。正常查询和无充电订单时不发送消息。

## 功能

| 功能 | 说明 |
| --- | --- |
| 自动查找订单 | 查询当前月和上个月，覆盖跨月充电 |
| 低功率提醒 | 默认连续两条真实采样低于 20 W 时提醒 |
| 双账号监控 | 分别查询、保存状态，通知注明所属车辆 |
| 防重复提醒 | 每个订单只提醒一次，重复采样不会重复计数 |
| 接口异常提醒 | HTTP 错误、网络失败、业务错误或异常响应时通知 |
| 异常恢复 | 持续异常只提醒一次，查询恢复后自动重新启用提醒 |
| 推送失败重试 | ShowDoc 未接受请求时，下一轮继续重试 |
| 无额外依赖 | 使用 Python 标准库，无需安装 requests |

**低功率表示进入低功率阶段，不等于已经充满或断电。脚本只查询和提醒，不控制充电设备。**

## 运行环境

- Python **3.9 或以上**。
- Linux 青龙面板；也可在 Linux/macOS 本地运行。
- 使用 `fcntl` 文件锁，不支持直接在原生 Windows 上运行。
- 有效的莱充账号凭证和 [ShowDoc 专属推送地址](https://push.showdoc.com.cn)。

## 青龙安装

### 1. 上传脚本

将 [laichon_monitor.py](laichon_monitor.py) 上传至青龙的 **脚本管理**。更新时覆盖同名脚本，保留原有状态文件。

### 2. 配置环境变量

在青龙的 **环境变量** 中添加并启用：

| 变量 | 必填 | 内容或默认值 |
| --- | --- | --- |
| `LAICHON_TOKEN` | 是 | 第一账号的 Authorization，可带 `bearer ` 前缀，也可只填令牌 |
| `LAICHON_OPENID` | 是 | 同一账号请求头中的 openid |
| `SHOWDOC_PUSH_URL` | 是 | 完整 ShowDoc 地址：`https://push.showdoc.com.cn/server/api/push/你的token` |
| `LAICHON_NAME` | 否 | 第一账号显示名称，默认 `我的车` |
| `LAICHON_TOKEN_2` | 否 | 第二账号的 Authorization，须与 OPENID_2 成对填写 |
| `LAICHON_OPENID_2` | 否 | 第二账号的 openid |
| `LAICHON_NAME_2` | 否 | 第二账号显示名称，默认 `老婆的车` |
| `LAICHON_POWER_THRESHOLD` | 否 | 功率阈值，单位 W，默认 `20`，须大于 0 |
| `LAICHON_STATE_FILE` | 否 | 第一账号状态文件，默认脚本旁的 `.laichon_state.json` |

从自己已登录的莱充小程序请求头中获取 TOKEN 和 OPENID；两者必须来自同一账号。凭证失效后重新获取并更新，脚本不会自动登录或刷新 Token。

**不要用逗号拼接两个账号的凭证。** 第二账号使用带 `_2` 的两个变量，不填写时只监控第一账号。两个账号共用 ShowDoc 地址、功率阈值和一个定时任务；某个账号接口失败会继续查询另一个账号。

如果两辆车的订单都属于同一个微信账号，只配置第一账号即可，脚本会监控该账号下所有返回的充电中订单。

### 3. 创建定时任务

| 项目 | 内容 |
| --- | --- |
| 名称 | `莱充充电监控` |
| 命令 | `task laichon_monitor.py` |
| 定时规则 | `*/5 * * * *` |

保存后手动执行一次，查看是否成功发现充电订单和输出功率。

模拟日志：

```text
[我的车] 找到 1 个充电中订单；提醒阈值 < 20 W
[我的车] 订单 示例订单：最近两条功率：326.3 → 326.9 W
[老婆的车] 找到 0 个充电中订单；提醒阈值 < 20 W
```

### 4. 可选：测试推送

```text
task laichon_monitor.py --test-notify
```

该命令只使用 SHOWDOC_PUSH_URL，会发送一条真实测试消息，不查询莱充账号，也不改变订单提醒状态。无需定时执行。

## 低功率提醒规则

从 `charging_details` 读取功率，按数字键表示的秒数排序，结合 `startTimestamp` 确定采样时间。只有同时满足以下条件才提醒：

1. 订单状态为 `3`，仍在充电中。
2. 最新采样距离充电开始至少 10 分钟。
3. 最后两条功率均**严格小于**阈值，默认 20 W；等于阈值不触发。
4. 两条采样间隔为 4～7 分钟。
5. 最新采样没有超过 15 分钟未更新，也没有明显的未来时间异常。
6. 订单尚未提醒，且本次有新的采样，或调整了阈值。

“连续两条”指设备采样记录，不是重复执行两次脚本。首次运行时，最后两条历史采样已符合条件就会直接提醒。数据缺失、陈旧或无效时不当作 0 W，并在日志中提示。

推送包含车辆名称、订单、地点、设备、插口、采样时间和功率变化。

## 接口异常与 Token 失效

订单列表或详情接口请求失败时，会通过 ShowDoc 发送“莱充接口请求异常”，注明对应车辆：

- HTTP 401/403 或非零业务码：提示检查凭证，登录失效时更新对应账号的 TOKEN 和 OPENID。
- 网络连接失败：提示检查网络，不直接认定为 Token 过期。
- 持续异常：同一账号只提醒一次，避免每 5 分钟重复发送。
- 查询恢复：一次完整账号查询成功后清除异常标记，下次异常可重新提醒。

ShowDoc 仅返回 `error_code: 0` 时才算接受推送请求；服务接受不等于微信最终送达。若 ShowDoc 同时不可达，日志会记录错误，下一轮尝试重发。通知直接调用 ShowDoc，不依赖青龙系统通知配置。

## 没有充电订单时的请求

每轮会查询每个账号当前月、上个月的订单列表；每个充电订单再查询一次详情。

| 场景 | 每轮请求数 |
| --- | --- |
| 一个账号，无充电订单 | 2 次列表请求 |
| 两个账号，无充电订单 | 4 次列表请求 |
| 有充电订单 | 每个充电订单增加 1 次详情请求 |

无订单时仍查询列表，以便发现下一次充电和登录失效。正常无订单时不推送。平台限流规则尚未确认，可按实际情况调整定时频率。

## 状态文件

```text
.laichon_state.json       # 第一账号的采样、订单提醒和接口异常记录
.laichon_state_2.json     # 第二账号的独立记录
.laichon_state.lock       # 防止监控任务同时运行
```

自定义状态路径时，第二账号在扩展名前追加 `_2`，例如 `monitor.json` 对应 `monitor_2.json`。

更新脚本时保留状态文件；删除后，符合条件的订单或持续接口异常会重新提醒。真实凭证、推送地址和运行状态不需要提交到仓库，`.gitignore` 已排除默认状态文件、`.env`、日志和 Python 缓存；自定义状态文件应放在仓库外。

## 本地运行与验证

在 Linux/macOS 上配置相同环境变量后运行：

```sh
python3 laichon_monitor.py
```

运行自动化测试：

```sh
python3 -m unittest -v
```

目前有 20 项测试，覆盖功率阈值、重复及陈旧采样、跨月查询、账号独立处理、异常去重与恢复、推送失败重试和 ShowDoc 响应校验。测试使用模拟接口，不访问真实账号，也不发送微信消息。

## 当前限制

- 莱充接口来自提供的请求样本；平台改变格式后可能需要调整脚本。
- 列表响应没有提供分页信息，本版只读取返回的 `data.list`，无法保证获取未返回的分页订单。
- 最多配置两个账号，支持每个账号下多个充电订单。
- 不会自动登录、刷新 Token、停止充电或单独发送订单结束提醒。
- 功率阈值用于提醒查看充电情况，不用于判断电池已经充满。
